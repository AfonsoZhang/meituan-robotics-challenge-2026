# 逐块观察的三块序列集成

2026-09-08，本机仿真开发实验，来源标识 `VISION-SEQUENCE-20260908`。示例顺序黄 → 绿 → 蓝，分别放到 P1、P2、P3，不是组委会正式口令。

## 已接入的流程

`bash demo/run.sh --sequence --timeout 180` 在同一个 Gazebo 世界中逐块执行。每块开始前重新到观察位，采集当前 RGB-D 与时间戳 TF，检查几何与深度门限，再修正该块源位置。黄块沿用 V2 观察位，绿、蓝使用 V1 的等价关节分支；原始观察位出处见 `demo/data/vision-provenance.json`。

场景不在两次抓取之间复位，先前放好的电池保留。每个阶段按自己的颜色和目标位评估，其他三块全部纳入移动检查，包括已放到目标位的电池。失败即不执行下一块，记录 `not_executed`。输出每块的视频、快照、轨迹与 summary；主视频不包含之前的观察动作，世界内总耗时另计。

局部修正采用最后四个高位接近点逐渐引入平移，穿钩与提升保持该修正，搬运段回到固定目标。远端过渡路径保持原样，以避开对原有接近奇异位形的过渡段进行不必要的平移 IK。这个策略并未补齐完整路径碰撞验证；执行期间仍开环。

## 已发现的问题

首轮黄块通过，绿块识别也通过，但对整段过渡路径平移时，第 50 点局部 IK 残差超门限，程序在绿块抓取前停止，蓝块未执行。保留该失败，没有放宽 IK 门限；改为只在末端高位接近段引入修正后，三块局部 IK 均通过。

第二轮黄块通过（中心误差 1.993 mm）；绿块通过当前放置判定，但误差 11.428 mm、覆盖率 77.172%，精度问题仍在。蓝块被提起并搬运后掉落，最终距 P3 195.852 mm、覆盖率 0。控制器三次均返回成功，说明不能用动作接口返回值代替搬运结果。

蓝块约在自身抓取开始后 41–42 s 的搬运末段发生突变；掉落前已连续离台超过 13 s。TCP 跟踪误差峰值约 0.877 mm。仅凭这些数据不能将原因归为相机、控制误差、滑脱或碰撞。

诊断版给蓝块四个碰撞体加 60 Hz 接触传感器，通过 `/demo/blue_contacts` 记录接触对，只用于审计，不进入控制。传感器不改质量、形状、摩擦或附着方式，但加入观测后的运行是新实验，不能把新接触事件倒推为上一轮已测事实。

这是四次开发尝试，期间实现有变化，不是同一版本的 2/4 成功率试验。第 3、4 次五个核心代码文件哈希一致，连续两次通过，也不足以估计稳定成功率或证明旧蓝块问题已经修复。

第 4 次结束时，黄/绿/蓝内框覆盖率分别为 84.444%、77.256%、77.044%，均直立且位于各自外框内。三块阶段的世界内总时间约 288.5 s，包括观察与连接动作；不包含最初控制器启动与重力恢复。三段抓取视频拼接不包含观察运动，视频顶部已标明省略观察、各块计时重置，不能作为连续任务计时视频。

第 3、4 次蓝块接触记录均只出现钩具和地面接触对，未记录到机械臂其他部位；但这两次没有掉落，不能用它们排除第 2 次的碰撞可能，更不能将接触传感器加入当作物理修复。`contact_collision_check` 通用评估字段仍表示未完成全场景碰撞审计；另存的 `blue-contacts.json` 仅覆盖蓝块接触。

## 适用边界

三块序列已接入逐块定位，尚无稳定三块成功率证据。旧蓝块问题仍需解决，绿块落点精度也需单独处理。理想光学外参、无真实深度噪声、缺少全路径碰撞检查和实物承载验证的限制均保留。


## 后续优先项

先调查绿、蓝约 11 mm 的共同释放偏移，并在带接触审计的固定版本上进行预先固定次数的三块重复试验，捕捉蓝块失败事件。没有失败瞬间的接触记录前，掉落原因保持未确认；不要仅凭成功视频宣称已修复。
