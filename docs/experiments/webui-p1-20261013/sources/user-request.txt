P1：视觉与规划模块集成
4. RGB-D 相机画面

浩然的视觉模块接入后，希望 Web UI 可以展示：

D435i RGB 实时画面。
Depth 深度图或伪彩色深度图。
检测到的电池及提环位置。
电池 ID、颜色和检测置信度。
提环位姿是否有效（ring_pose_valid）。
图像时间戳及数据是否过期。
最好能在 RGB 画面上叠加电池检测框、颜色标签和目标电池高亮。

目标是让我们知道系统现在看到了什么、准备抓哪一块电池。

当前已有 /mtc/perception/batteries 的消息契约，但 Web UI 尚未订阅。具体画面叠加方式可以等视觉模块正式接入后再确定。

5. MoveIt 规划状态

建烁的 Planner 接入后，希望显示：

当前正在规划哪个 Motion Primitive。
规划状态：等待、规划中、成功或失败。
当前轨迹的点数和预计执行时长。
是否通过关节限位检查。
是否通过碰撞检查。
起点一致性检查是否通过。
规划失败的具体原因。
例如 V1 当前遇到的 EXCEEDS_STATE_WATCHDOG，希望能在页面上直接看到原因，而不是只显示“规划失败”。

如果后续开发成本允许，可以考虑增加 RViz 或独立 3D 视图，用于查看机器人、规划路径、障碍物及目标工位。

但这部分优先级低于基础状态显示，不需要第一轮就完成。

6. 工具与电池状态

需要显示：

当前工具类型：V1 Passive Hook / V2 Magnetic Latch。
工具当前状态：Detached、Engaging、Attached、Releasing、Fault。
当前工具关联的电池 ID。
是否已经独立确认挂载。
当前挂载证据等级。
是否完成试提和落座验证。
工具状态和挂载确认必须分开显示，不能因为工具发出了接合指令，就直接认为抓取成功。
