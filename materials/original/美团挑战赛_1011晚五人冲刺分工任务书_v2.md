## 02｜孙嘉明｜FSM / ROS 2 Action / Motion Execution（今晚 P0）

**目标：** 将已合并到 `main` 的 C++ FSM Core 包装为可供 ROS 2 节点调用的 Action 层，并向张叔阳交付能够验证的最小 Mock 通路。

5. 根据已验证的只读工作空间 `/home/aaet/aubo_driver_validation_ws`，整理 `docs/setup/AUBO_ROS2_DRIVER_JAZZY.md` 初稿：实际源码版本、依赖、编译、Fake Hardware 启动、MoveIt/RViz 检查、控制器与关节反馈检查。未知命令标 `NEEDS VERIFICATION`，**不得猜测 launch 名称**。

**22:30 验收：** 提供 C++ Action 可编译/可运行结果、Mock Goal 与 Cancel 日志、接口尚未接通的位置、驱动 SOP 路径及 Git commit。**今晚不以接上真实机械臂作为验收条件。**

## 03｜常建烁｜MoveIt 2 运动规划（今晚 P0）

**目标：** 已知一个含坐标系的有效目标 6D Pose，能在 AUBO S3 的 Fake Hardware/MoveIt 配置中规划，输出 FSM 可消费的完整轨迹。

**今晚必须完成**

1. 在只读参考的 AUBO 驱动验证工作空间核对实际 **Planning Group、robot model、6 个关节名称/顺序、base frame、EE link、控制器名称**；将核验值写入 `PLANNING_HANDOFF.md`。
2. 用可复现的**固定有效 6D Pose** 测试规划；给出规划调用方式、返回状态、规划耗时，以及完整关节轨迹（关节名、points、`time_from_start`、位置；如有则速度/加速度）。**仅 RViz 截图不算通过。**
3. 设计/实现面向 `PlannerPort::plan(const PlanTarget&)` 的转换层，保留 `frame_id`、四元数、姿态约束、规划失败原因；明确最终返回的 `PlanResult` 如何提供 `MotionCommand`/`TimedTrajectory`。不改动 C++ FSM Core 公共契约。
4. 为**单块电池基础任务**准备最低限度的运动阶段：预抓取、接近、试提/抬起、搬运至 T0、下降、撤离。未经现场标定的接触动作只能作为**规划意图或仿真验证**，不得认定已经安全可执行。

**22:30 验收：** 一条真实输出的完整轨迹文件/日志、使用的配置版本、可复现命令、PlannerPort 映射、当前碰撞场景和 TCP 是否可信的说明、Git commit。
